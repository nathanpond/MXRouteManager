Rewrite `MXRouteManager/Views/SettingsView.swift` so the placeholder section is gone and the real form takes its place.

View state:

```swift
@Environment(AppSettings.self) private var settings
@State private var apiKeyInput: String = ""
@State private var statusMessage: String?
@State private var errorMessage: String?
```

In `body`, start with `@Bindable var settings = settings` so the text fields can bind to the `@Observable` model.

Grouped `Form` with two sections:

1. `Section("Connection")`:
   - `TextField("Server", text: $settings.serverHostname, prompt: Text("eagle.mxlogin.com"))`
   - `TextField("Username", text: $settings.username, prompt: Text("DirectAdmin username"))`
   - Both: `.textFieldStyle(.roundedBorder)` is not needed inside a grouped Form — leave the default. Add `.autocorrectionDisabled()` to both; a "corrected" hostname is a silently broken credential.
   - `.onSubmit { settings.normalize() }` on each field.
   - Footer text describing where these come from: the mail server hostname and the DirectAdmin username from the MXRoute welcome email.

2. `Section("API Key")`:
   - When `settings.hasAPIKey`: a row with `Label("API key stored in Keychain", systemImage: "checkmark.seal.fill")` (`.foregroundStyle(.green)` on the symbol via `.symbolRenderingMode` or a tinted Label is fine) and a trailing `Button("Remove", role: .destructive)` calling `removeKey()`.
   - Always: `SecureField("API Key", text: $apiKeyInput, prompt: Text(settings.hasAPIKey ? "Enter a new key to replace" : "Paste your MXRoute API key"))`, with `.onSubmit { saveKey() }`.
   - A `Button("Save to Keychain") { saveKey() }` disabled when `apiKeyInput.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty`.
   - Footer: keys are created at `panel.mxroute.com/api-keys.php`.

Below the sections, a status area: `errorMessage` in `.red` if set, else `statusMessage` in `.secondary` if set, else — when `!settings.isConfigured` — a muted "Enter a server, username, and API key to finish setup." line.

Private methods:

```swift
private func saveKey() {
    let key = apiKeyInput.trimmingCharacters(in: .whitespacesAndNewlines)
    guard !key.isEmpty else { return }
    do {
        try settings.saveAPIKey(key)
        apiKeyInput = ""
        errorMessage = nil
        statusMessage = "API key saved to Keychain."
    } catch {
        statusMessage = nil
        errorMessage = "Could not save the API key: \(error.localizedDescription)"
    }
}

private func removeKey() { /* symmetric: try settings.removeAPIKey(); statusMessage = "API key removed from Keychain." */ }
```

Add `.onDisappear { settings.normalize() }` to the `Form` so values typed but never submitted are trimmed when the window closes.

Bump the frame to `.frame(width: 460, height: 360)` — the Phase 1 height of 200 clips two sections.

Keep `#Preview { SettingsView().environment(AppSettings()) }` — the environment value is required or the preview traps.

Constraints, all load-bearing:

- NEVER pre-fill the `SecureField` from the Keychain, and never add a "show key" toggle. The stored key has no reason to be rendered again; loading it into view state is the one move that puts the secret back into memory the UI owns, and CONF/security constraint is that it lives in the Keychain only.
- Do NOT save the key on every keystroke (no `.onChange(of: apiKeyInput)` write). Commit only on the button or `onSubmit`, otherwise every prefix of the key gets written to the Keychain.
- Do NOT clear the stored key when `apiKeyInput` is empty. Empty input means "not changing it", not "delete it" — removal is the explicit Remove button.
- Do NOT add a "Test Connection" button, any `URLSession` call, or a domains fetch. That is CONF-04 and belongs to Phase 3, which has the API client; a stub here would have to be torn out.
- Do NOT `print`/`NSLog` the key or the input field anywhere.

Troubleshooting hints if a step fails:
- Values do not survive relaunch → `@AppStorage` keys differ between write and read, or `AppSettings` was constructed per-view instead of injected from the app scene (plan 02-02, Task 3).
- Save reports an error → read the surfaced `errorDescription`; `-25300` is item-not-found (an `SecItemUpdate`/`SecItemAdd` ordering bug in `KeychainService.save`), `-34018` would mean an entitlement problem (not expected on this project).
- The API key appears in the plist → stop; something is writing the key through `AppSettings`/`@AppStorage`. That is a hard failure of the phase's security constraint, not a cosmetic issue.

Cosmetic complaints about spacing, wording, or window size go to the Phase 5 polish pass (POL-01/POL-02) as issues rather than being iterated on here.
