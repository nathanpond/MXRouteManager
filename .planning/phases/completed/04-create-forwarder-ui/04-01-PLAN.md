```swift
/// The verdict on what the user has typed into the alias field.
/// `.empty` is deliberately distinct from `.invalid` — an untouched field
/// must disable Create WITHOUT scolding the user with a red error.
nonisolated enum AliasValidation: Equatable {
    case empty
    case valid(normalized: String)
    case invalid(reason: String)

    var normalizedAlias: String? {
        if case .valid(let normalized) = self { return normalized }
        return nil
    }

    /// The message to show under the field, or nil when there is nothing to say.
    var errorReason: String? {
        if case .invalid(let reason) = self { return reason }
        return nil
    }
}

nonisolated enum AliasValidator {
    static let maxLength = 64
    private static let allowed = CharacterSet(charactersIn: "abcdefghijklmnopqrstuvwxyz0123456789._-+")

    static func validate(_ raw: String) -> AliasValidation { … }
}
```

`validate` runs these steps **in this exact order** — the order is what makes the message specific instead of generic:

1. `let trimmed = raw.trimmingCharacters(in: .whitespacesAndNewlines)`; if `trimmed.isEmpty` → `.empty`.
2. If `trimmed.contains("@")` → `.invalid(reason: "Enter just the part before the @.")` — checked FIRST because pasting a whole address is the single most likely mistake and "invalid character" would be a useless answer to it.
3. If `trimmed.rangeOfCharacter(from: .whitespacesAndNewlines) != nil` → `.invalid(reason: "Aliases can't contain spaces.")` (an interior space survives trimming).
4. If `trimmed.count > maxLength` → `.invalid(reason: "Keep the alias to \(maxLength) characters or fewer.")`.
5. `let normalized = trimmed.lowercased()`. Lowercasing here, not at submit time: DirectAdmin stores mailboxes lowercase, so a user typing `Sales` gets `sales@…` — the confirmation in plan 04-03 must show what was ACTUALLY created, not what was typed.
6. If `normalized.unicodeScalars.contains(where: { !allowed.contains($0) })` → `.invalid(reason: "Use letters, numbers, and . _ - + only.")`.
7. If `normalized.hasPrefix(".") || normalized.hasSuffix(".")` → `.invalid(reason: "An alias can't start or end with a dot.")`.
8. If `normalized.contains("..")` → `.invalid(reason: "An alias can't contain two dots in a row.")`.
9. Otherwise `.valid(normalized: normalized)`.

Constraints:

- Keep it a pure static function: no `AppSettings`, no networking, no `@Observable`, no logging. Every rule must be decidable from the string alone, or the tests in this task cannot exist.
- Do NOT try to implement full RFC 5322 (quoted strings, unicode local parts). The rules above are the practical DirectAdmin-safe subset and are exactly what UI-02 asks for; a "more correct" validator that accepts `"weird name"@…` would then be rejected by the API with a confusing error.
- Do NOT strip disallowed characters silently as the user types — the field must show what was typed and explain the problem. Silent mutation of a text field fights the cursor.

Then create `MXRouteManagerTests/AliasValidatorTests.swift` — `import Testing`, `@testable import MXRouteManager`, one `@Suite("Alias validation")`. No mock network, no `withMockNetwork` (this touches nothing shared). Cover at minimum:

- `""` and `"   "` → `.empty`
- `"sales"` → `.valid(normalized: "sales")`
- `"Sales.Team"` → `.valid(normalized: "sales.team")` (normalization)
- `"  sales  "` → `.valid(normalized: "sales")` (outer whitespace trimmed)
- `"first+tag_1-2"` → valid (each allowed punctuation)
- `"sales@example.com"` → invalid, reason mentions the `@` (assert with `#expect(result.errorReason?.contains("@") == true)`)
- `"my alias"` → invalid, reason mentions spaces
- `"sales!"` → invalid (disallowed character)
- `".sales"` and `"sales."` → invalid (leading/trailing dot)
- `"sa..les"` → invalid (double dot)
- `String(repeating: "a", count: 65)` → invalid; `String(repeating: "a", count: 64)` → valid (boundary both sides)

Assert on the case, not on exact prose, except where noted — brittle full-string equality would make future wording tweaks fail the suite. Use `#expect(AliasValidator.validate("sales") == .valid(normalized: "sales"))` where the value matters.

Create `MXRouteManager/Models/CreateForwarderModel.swift` (`import SwiftUI` — it needs `@AppStorage` — and `import Foundation`).

**File-scope state enums.** Both `Equatable` so plan 04-03 can pass them straight to `.animation(_:value:)`:

```swift
enum LoadState<Value: Equatable>: Equatable {
    case idle
    case loading
    case loaded(Value)
    case failed(String)   // already-user-facing text, never a raw Error

    var value: Value? { if case .loaded(let v) = self { return v }; return nil }
    var isLoading: Bool { if case .loading = self { return true }; return false }
}

enum SubmitState: Equatable {
    case idle
    case submitting
    case succeeded(Forwarder)
    case failed(String)
}
```

**The model:**

```swift
@Observable
@MainActor
final class CreateForwarderModel {
    enum Keys { static let lastDomain = "mxroute.lastDomain" }

    private let settings: AppSettings
    private let makeClient: @MainActor (AppSettings) -> MXRouteClient

    @ObservationIgnored @AppStorage(Keys.lastDomain) private var storedLastDomain: String = ""

    private(set) var domains: LoadState<[String]> = .idle
    private(set) var accounts: LoadState<[EmailAccount]> = .idle
    private(set) var submitState: SubmitState = .idle
    var aliasInput: String = ""
    var selectedDestination: String = ""

    /// Which credentials the cached `domains` were fetched with. Reloading on
    /// change is what stops a domain list fetched with the old API key from
    /// surviving a credential edit in Settings.
    @ObservationIgnored private var loadedFingerprint: String?
    @ObservationIgnored private var accountsCache: [String: [EmailAccount]] = [:]

    init(settings: AppSettings, makeClient: (@MainActor (AppSettings) -> MXRouteClient)? = nil) {
        self.settings = settings
        self.makeClient = makeClient ?? { MXRouteClient.live(settings: $0) }
    }
}
```

`@MainActor` is written explicitly even though the target defaults to it — this type is read by SwiftUI on every render and the annotation documents that, and survives a future build-setting change.

`makeClient` is injectable for one concrete reason used in plan 04-02: `#Preview` must be able to hand in a credential-less client so opening the SwiftUI canvas never fires a real API request or a Keychain prompt. Do not delete it as "unused".

**Persisted selection** — follow the `AppSettings` idiom exactly:

```swift
var selectedDomain: String {
    get { access(keyPath: \.selectedDomain); return storedLastDomain }
    set { withMutation(keyPath: \.selectedDomain) { storedLastDomain = newValue } }
}
```

**Derived properties:**

```swift
var aliasValidation: AliasValidation { AliasValidator.validate(aliasInput) }

/// The address as it will actually exist, for the live preview under the field.
var previewAddress: String? {
    guard let alias = aliasValidation.normalizedAlias, !selectedDomain.isEmpty else { return nil }
    return "\(alias)@\(selectedDomain)"
}

var canSubmit: Bool {
    aliasValidation.normalizedAlias != nil
        && !selectedDomain.isEmpty
        && !selectedDestination.isEmpty
        && submitState != .submitting
}
```

**Credential fingerprint** (private): `"\(settings.serverHostname)|\(settings.username)|\(settings.hasAPIKey)"`. Never include the key itself — it is not in `AppSettings` and must never be.

**`func loadDomains(force: Bool = false) async`:**

1. `let fingerprint = credentialFingerprint`.
2. If `!force`, `case .loaded = domains`, and `loadedFingerprint == fingerprint` → return immediately. This early return is what makes the second popover open instant (the ten-second core value); without it every open re-hits the network.
3. If credentials changed, also clear `accountsCache` — mailboxes fetched under other credentials are meaningless.
4. `domains = .loading`.
5. `do { let list = try await makeClient(settings).listDomains(); guard !Task.isCancelled else { return }; loadedFingerprint = fingerprint; domains = .loaded(list); reconcileSelectedDomain(with: list) } catch { guard !Task.isCancelled else { return }; domains = .failed(Self.message(for: error)) }`.

**`private func reconcileSelectedDomain(with list: [String])`:** if the list is empty → `selectedDomain = ""`. Else if `!list.contains(selectedDomain)` → `selectedDomain = list[0]`. This is what stops a remembered domain that has since been removed from MXRoute (or a first-ever launch with `""`) from leaving the picker bound to a value that is not in its options — SwiftUI renders that as a blank picker with no way out.

**`func loadAccounts(for domain: String, force: Bool = false) async`:**

1. `guard !domain.isEmpty else { accounts = .idle; selectedDestination = ""; return }`.
2. If `!force`, `let cached = accountsCache[domain]` → `accounts = .loaded(cached)`, `reconcileDestination(with: cached)`, return.
3. `accounts = .loading`; `selectedDestination = ""` (a destination from the previous domain must never survive a domain switch — submitting it would forward to a mailbox on a different domain).
4. `do { let list = try await makeClient(settings).listEmailAccounts(domain: domain) … }` then, before assigning anything: `guard !Task.isCancelled, domain == selectedDomain else { return }`. **Both** guards are required: `.task(id:)` cancellation covers the fast-switch case, and the `domain == selectedDomain` check covers a response that lands after a re-selection the task-id did not distinguish. On success cache it (`accountsCache[domain] = list`), set `.loaded(list)`, `reconcileDestination(with: list)`.
5. On error, same `guard !Task.isCancelled, domain == selectedDomain else { return }` before `accounts = .failed(Self.message(for: error))` — an error banner from a load the user has already navigated away from is the exact bug this guard exists to prevent.

**`private func reconcileDestination(with list: [EmailAccount])`:** if `selectedDestination` is empty or absent from `list.map(\.email)` → `selectedDestination = list.first?.email ?? ""`. The client already returns accounts sorted by address, so `.first` is deterministic; do NOT re-sort here.

**`func submit() async`:**

```swift
guard canSubmit, let alias = aliasValidation.normalizedAlias else { return }
let domain = selectedDomain
let destination = selectedDestination
submitState = .submitting
do {
    let forwarder = try await makeClient(settings).createForwarder(
        domain: domain, alias: alias, destinations: [destination]
    )
    submitState = .succeeded(forwarder)
} catch {
    submitState = .failed(Self.message(for: error))
}
```

Notes that matter:
- Submit deliberately does NOT check `Task.isCancelled` and does NOT bail on cancellation. A create is a side effect that already happened on the server; swallowing its result would leave the user unsure whether the forwarder exists. Capture `domain`/`destination` into locals first so a mid-flight selection change cannot rewrite what gets reported.
- It sends the **normalized** alias, so `forwarder.email` is exactly the address that now exists.
- `destinations: [destination]` — a single-element array. Multi-destination forwarders are v2 (MGMT-02); do not add a multi-select here.

**`func reset()`** (the "Create Another" action): `aliasInput = ""`, `submitState = .idle`. Deliberately KEEPS `selectedDomain` and `selectedDestination` — the overwhelmingly common repeat case is another alias on the same domain going to the same mailbox, and re-picking both would blow the ten-second budget.

**`private static func message(for error: Error) -> String`:** `(error as? MXRouteError)?.errorDescription ?? error.localizedDescription` — the same idiom `SettingsView.testConnection()` already uses, so API messages reach the user verbatim.

Constraints:

- No `URLSession`, no `URLRequest`, no `SecItem`, no `KeychainService` in this file — all networking goes through `makeClient(settings)`, which is the only place credentials are assembled.
- Do NOT add a `Timer`, polling, or auto-refresh. Loads happen from the view's `.task`/`.task(id:)` and the retry button only; the API rate-limits reads.
- Do NOT store an `MXRouteClient` as a property. Build one per call — it snapshots credentials at construction, so a cached client would keep using an API key the user has since replaced.
- Do NOT import `AppKit` or reference any `View` type here. The model must stay renderable-agnostic; plan 04-02 owns every pixel.
- No new tests are required in this task (the model's behavior is verified by the live checkpoint in 04-03), but the existing 41 + Task 1's tests must stay green.
