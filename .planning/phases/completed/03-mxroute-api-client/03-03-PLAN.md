```swift
func listEmailAccounts(domain: String) async throws -> [EmailAccount] {
    let domain = domain.trimmingCharacters(in: .whitespacesAndNewlines)
    guard !domain.isEmpty else {
        throw MXRouteError.invalidRequest(message: "Choose a domain before loading its email accounts.")
    }
    guard let accounts = try await send([EmailAccount].self, method: "GET", pathComponents: ["domains", domain, "email-accounts"]) else {
        throw MXRouteError.decoding(message: "The email accounts response contained no data.")
    }
    return accounts.sorted { $0.email.localizedCaseInsensitiveCompare($1.email) == .orderedAscending }
}
```

Notes that matter:

- Sort here rather than in the view: Phase 4's destination picker renders this array directly, and DirectAdmin returns mailboxes in creation order, which reads as random in a dropdown.
- Reuse `send`; do NOT build a `URLRequest` in this method. Auth headers, the 401 mapping, and the envelope handling all live in the pipeline, and a second request path is how a header goes missing on one endpoint only.
- Do NOT filter out suspended accounts here — the model carries `suspended` so the UI can decide; silently dropping a mailbox in the client makes "my account is missing from the list" undebuggable.
- Do NOT add pagination or query parameters; the endpoint takes none.

Then, in the `MXRouteClient` struct body:

```swift
@discardableResult
func createForwarder(domain: String, alias: String, destinations: [String]) async throws -> Forwarder {
    let domain = domain.trimmingCharacters(in: .whitespacesAndNewlines)
    let alias = alias.trimmingCharacters(in: .whitespacesAndNewlines)
    let destinations = destinations
        .map { $0.trimmingCharacters(in: .whitespacesAndNewlines) }
        .filter { !$0.isEmpty }

    guard !domain.isEmpty else { throw MXRouteError.invalidRequest(message: "Choose a domain for the forwarder.") }
    guard !alias.isEmpty else { throw MXRouteError.invalidRequest(message: "Enter an alias for the forwarder.") }
    guard !destinations.isEmpty else { throw MXRouteError.invalidRequest(message: "Choose at least one destination for the forwarder.") }

    let body = try JSONEncoder().encode(CreateForwarderBody(alias: alias, destinations: destinations))
    let created = try await send(
        Forwarder.self,
        method: "POST",
        pathComponents: ["domains", domain, "forwarders"],
        body: body
    )
    return created ?? Forwarder(alias: alias, email: "\(alias)@\(domain)", destinations: destinations)
}
```

Why each piece:

- The `created ?? Forwarder(...)` fallback is the crux: the OpenAPI spec declares `201 Forwarder created` with **no** response body, so `send` legitimately returns `nil` on success. Throwing there would report a failure for a forwarder that was actually created — the single worst bug this feature can have. Building the value locally from the inputs matches what the server would have echoed (`alias@domain`).
- Local validation throws `.invalidRequest` **before** the request, so the UI gets an instant, specific message instead of a round-trip and a generic `VALIDATION_ERROR`. It does NOT replace server validation — a malformed local part still comes back as an API error and must surface as-is.
- Do NOT validate the alias against a regex here; alias rules belong to UI-02 in Phase 4 and to the server. The client only rejects empty.
- Do NOT deduplicate or lowercase destinations beyond trimming, and do NOT reject `:blackhole:` / `:fail:` — they are valid MXRoute destinations.
- Do NOT retry on `RATE_LIMITED` or `CONFLICT`; both must reach the user.
- `@discardableResult` because Phase 4 may only need "it worked".
