
Add the action:

```swift
private func testConnection() {
    settings.normalize()
    isTesting = true
    errorMessage = nil
    statusMessage = "Testing connection…"

    Task {
        defer { isTesting = false }
        do {
            let client = MXRouteClient.live(settings: settings)
            let domains = try await client.listDomains()
            errorMessage = nil
            statusMessage = domains.count == 1
                ? "Connected — 1 domain found."
                : "Connected — \(domains.count) domains found."
        } catch {
            statusMessage = nil
            errorMessage = (error as? MXRouteError)?.errorDescription ?? error.localizedDescription
        }
    }
}
```

Why each detail:

- `settings.normalize()` first: a hostname pasted with a trailing space becomes an invalid `X-Server` header and the API answers with a confusing error rather than "you typed a space".
- `defer { isTesting = false }` inside the `Task`, not after it: the flag must clear on the throwing path too, or the button stays dead after the first failure.
- The catch prefers `MXRouteError.errorDescription` — that string IS the demo ("with a bad key it shows the decoded API error message"). `error.localizedDescription` is only the fallback for a non-`MXRouteError`.
- The `Task` body runs on the MainActor (the view is MainActor-isolated), so assigning `@State` from it is safe; `await` suspends without blocking the UI. Do NOT add `Task.detached`, `DispatchQueue`, or `@MainActor in` — they either break state assignment or are redundant here.
- The button is gated on `settings.isConfigured` so the common "nothing entered yet" case never becomes a `.notConfigured` error toast.

Also extend the existing status `Section` so a stale success message cannot outlive a later failure — it already prefers `errorMessage` over `statusMessage`, so just make sure `testConnection()` clears the other one on each branch (as written above). No other change to that section.

Constraints:

- Do NOT construct `MXRouteClient(credentials:...)` directly here or read the Keychain in the view — `MXRouteClient.live(settings:)` is the one place that assembles credentials.
- Do NOT display, log, or interpolate the API key anywhere (not even a masked prefix).
- Do NOT auto-run the test on appear or on every keystroke — the API rate-limits reads at 100/minute and an implicit request on typing is a surprise. It runs on the button only.
- Do NOT add domain-list caching, a stored `[String]` of domains, or any menu-bar wiring. Phase 4 owns fetching domains for the UI; a cache here would be dead code.
- Do NOT change the `Form`'s `.frame(width: 460, height: 360)` unless the new section clips; if it does, raise the height only.
- Keep `#Preview { SettingsView().environment(AppSettings()) }` working — the preview must not fire a request.
