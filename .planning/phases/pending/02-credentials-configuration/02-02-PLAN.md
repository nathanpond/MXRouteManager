  <action>
Create `MXRouteManager/Models/AppSettings.swift` (`import SwiftUI`, `import Foundation`).

```swift
@Observable
final class AppSettings {
    enum Keys {
        static let serverHostname = "mxroute.serverHostname"
        static let username = "mxroute.username"
    }

    @ObservationIgnored @AppStorage(Keys.serverHostname) private var storedServerHostname: String = ""
    @ObservationIgnored @AppStorage(Keys.username) private var storedUsername: String = ""

    private let keychain: KeychainService

    private(set) var hasAPIKey: Bool

    init(store: UserDefaults = .standard, keychain: KeychainService = .shared) {
        _storedServerHostname = AppStorage(wrappedValue: "", Keys.serverHostname, store: store)
        _storedUsername = AppStorage(wrappedValue: "", Keys.username, store: store)
        self.keychain = keychain
        self.hasAPIKey = keychain.hasKey
    }

    var serverHostname: String {
        get { access(keyPath: \.serverHostname); return storedServerHostname }
        set { withMutation(keyPath: \.serverHostname) { storedServerHostname = newValue } }
    }

    var username: String {
        get { access(keyPath: \.username); return storedUsername }
        set { withMutation(keyPath: \.username) { storedUsername = newValue } }
    }

    var isConfigured: Bool {
        !serverHostname.trimmed.isEmpty && !username.trimmed.isEmpty && hasAPIKey
    }

    func saveAPIKey(_ key: String) throws {
        try keychain.save(key.trimmed)
        hasAPIKey = true
    }

    func removeAPIKey() throws {
        try keychain.delete()
        hasAPIKey = false
    }

    func normalize() {
        serverHostname = serverHostname.trimmed
        username = username.trimmed
    }
}
```

Add a small `private extension String { var trimmed: String { trimmingCharacters(in: .whitespacesAndNewlines) } }` in this file (or inline the calls) — do not add a shared utilities file for one helper.

Why this exact shape:

- `@AppStorage` is a `DynamicProperty`; the `@Observable` macro cannot observe it, hence `@ObservationIgnored` on the stored pair plus manual `access(keyPath:)` / `withMutation(keyPath:)` in the computed accessors. That pairing is what makes `@AppStorage` persistence and SwiftUI observation coexist in a plain class — the requirement (CONF-02) names `@AppStorage` and the roadmap names an observable model, and this satisfies both with one source of truth.
- The `_storedServerHostname = AppStorage(wrappedValue:_:store:)` assignments in `init` are what make the defaults suite injectable for tests. Keep them even though the property declarations also carry defaults.
- `hasAPIKey` is a stored property mutated by `saveAPIKey`/`removeAPIKey`, NOT a computed `keychain.hasKey`. A computed version would hit the Keychain on every SwiftUI render pass and would never trigger an observation update, so the UI would not react to saving a key.
- Trim on `isConfigured`/`saveAPIKey`/`normalize()`, not inside the property setters. Trimming in the setter makes it impossible to type a space mid-edit and makes bound `TextField`s behave strangely.

Do NOT put the API key itself on this model — no `apiKey` property, no cached copy, not even a transient one. The key exists in the Keychain and, briefly, in the Settings view's local `@State` while being typed. Adding it here would put the secret into a long-lived app-wide object.

Do NOT add any networking, `testConnection()`, or a `URLSession` reference. Test Connection is CONF-04, Phase 3.

If the `@ObservationIgnored @AppStorage` + `access`/`withMutation` combination fails to compile, fall back to plain stored `serverHostname`/`username` properties with `didSet` writing to the injected `UserDefaults` under the same `Keys` values, and record the deviation explicitly in the summary — behaviour and key names must stay identical either way.

```swift
struct MXRouteManagerApp: App {
    @State private var settings = AppSettings()

    var body: some Scene {
        MenuBarExtra("MXRoute Manager", systemImage: "envelope.badge") {
            MenuBarContentView()
                .environment(settings)
        }
        .menuBarExtraStyle(.window)

        Settings {
            SettingsView()
                .environment(settings)
        }
    }
}
```

Notes that matter:

- `@State` (not `let`) is how an `@Observable` object gets a stable lifetime in an `App`; a plain `let` re-initialises nothing but also gives SwiftUI no ownership hook.
- Inject on BOTH scene contents. They are separate view hierarchies — the environment does not flow from one scene to another — and Phase 5 needs the popover to read `isConfigured` from the same object the Settings window writes.
- Use `.environment(settings)` (the `@Observable` overload), not `.environmentObject`.

Do NOT change the `MenuBarExtra` title/symbol, `.menuBarExtraStyle(.window)`, or anything in `MenuBarContentView` or `SettingsView` in this plan. `SettingsView` still shows its Phase 1 placeholder; plan 02-03 replaces it. An unread environment value is harmless.
