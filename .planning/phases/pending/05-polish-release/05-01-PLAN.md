Replace the current `unconfiguredSection` (a `Label` + a plain `SettingsLink`) with a real first-run panel, and make the header reflect that the app is not configured yet.

**1. Header becomes state-aware.** Today the header always says "New Forwarder", which is wrong above a setup panel — there is no forwarder to make yet. Change the two header values to depend on `settings.isConfigured`:

```swift
private var header: some View {
    HStack(spacing: 7) {
        Image(systemName: settings.isConfigured ? "arrow.turn.down.right" : "envelope.badge")
            .font(.system(size: 12, weight: .semibold))
            .foregroundStyle(.tint)
        Text(settings.isConfigured ? "New Forwarder" : "MXRoute Manager")
            .font(.headline)
        Spacer()
    }
    .padding(.horizontal, 16)
    .padding(.top, 14)
    .padding(.bottom, 12)
}
```

`envelope.badge` is the same symbol as the menu bar glyph, so the panel visibly belongs to the icon the user just clicked. Both symbol names are already in use in this project — do not substitute others.

**2. The welcome panel.** Rewrite `unconfiguredSection` as: one line of purpose, three numbered steps, then a prominent way into Settings.

```swift
private var unconfiguredSection: some View {
    VStack(alignment: .leading, spacing: 12) {
        Text("Create MXRoute email forwarders straight from the menu bar.")
            .font(.subheadline)
            .foregroundStyle(.secondary)
            .fixedSize(horizontal: false, vertical: true)

        VStack(alignment: .leading, spacing: 7) {
            setupStep(1) {
                Text("Create an API key at ")
                + Text("panel.mxroute.com/api-keys.php").font(.system(.caption, design: .monospaced))
            }
            setupStep(2) {
                Text("Copy the server and username shown on that page")
            }
            setupStep(3) {
                Text("Paste all three into Settings and save")
            }
        }

        SettingsLink {
            Label("Open Settings…", systemImage: "gearshape")
        }
        .buttonStyle(.borderedProminent)
        .simultaneousGesture(TapGesture().onEnded { NSApplication.shared.activate() })
    }
}

private func setupStep<Content: View>(_ number: Int, @ViewBuilder _ text: () -> Content) -> some View {
    HStack(alignment: .firstTextBaseline, spacing: 7) {
        Text("\(number)")
            .font(.system(.caption, design: .rounded).weight(.semibold))
            .foregroundStyle(.tint)
            .frame(width: 12, alignment: .trailing)
        text()
            .font(.caption)
            .foregroundStyle(.secondary)
            .fixedSize(horizontal: false, vertical: true)
    }
}
```

Notes on why this shape:

- The `.simultaneousGesture(TapGesture().onEnded { NSApplication.shared.activate() })` on the `SettingsLink` is **load-bearing and must survive** — this is an `LSUIElement` app, so without the explicit activation the Settings window opens behind whatever is frontmost and the first-run flow dead-ends with nothing visibly happening. The footer's `SettingsLink` carries the same modifier; keep both.
- `.buttonStyle(.borderedProminent)` here (the footer's stays `.borderless`) makes it the one obvious action on an otherwise informational panel.
- `Text(...) + Text(...)` concatenation is used so the URL renders monospaced inside a flowing sentence. Concatenation only works between `Text` values — do not put a `Link`, `Image`, or any other view on either side of the `+`, and do not apply `.foregroundStyle` to only one half (the outer `.font(.caption)`/`.foregroundStyle(.secondary)` in `setupStep` styles the whole run).
- The URL is deliberately **plain text, not a `Link`**. A clickable link is tempting, but an `LSUIElement` menu bar popover that opens a browser dismisses itself in the process, which reads as the app crashing on first run. The user has a browser; the address is copyable knowledge, not a required affordance.
- `fixedSize(horizontal: false, vertical: true)` on every text run: the popover is a fixed 320pt wide with no height, so any string that must wrap has to be told it may grow vertically or it silently truncates.

**3. Do not touch** the configured branch, `formSection`, `actionSection`, `footer`, the `.task` / `.task(id:)` loads, the `#Preview`, the `.frame(width: 320)`, or the `.background(.regularMaterial)`. Do not add `Form`, `GroupBox`, or `List` — all three impose macOS inset chrome that fights a 320pt popover. Do not use a hardcoded color (`Color(red:…)`, hex, `.white`, `.black`), and do not set `.preferredColorScheme` — the panel must follow the system appearance.

**4. Sanity-check the panel by eye.** Build and launch, then temporarily verify the unconfigured path renders without disturbing the user's real credentials: the `#Preview` at the bottom of the file constructs an `AppSettings()` and a credential-less client, and Xcode's canvas will show `unconfiguredSection` whenever the previewed settings are unconfigured. Prefer the preview canvas over removing the real API key — removing it is the human checkpoint's job in plan 05-03, not yours.

The two empty-array branches currently render one grey sentence each and offer nothing: `Text("No domains on this account.")` in `domainField` and `Text("No mailboxes on this domain.")` in `destinationField`. Both are reachable on a correctly configured account, and both are dead ends. Replace each with a symbol-led message that states the cause and offers a reload.

**1. Add one shared helper** (place it next to `setupStep`):

```swift
private func emptyState(_ message: String, hint: String, reload: @escaping () -> Void) -> some View {
    VStack(alignment: .leading, spacing: 6) {
        Label(message, systemImage: "info.circle")
            .font(.caption.weight(.medium))
            .foregroundStyle(.secondary)
            .imageScale(.small)
        Text(hint)
            .font(.caption)
            .foregroundStyle(.secondary)
            .fixedSize(horizontal: false, vertical: true)
        Button(action: reload) {
            Label("Reload", systemImage: "arrow.clockwise")
        }
        .controlSize(.small)
    }
}
```

`info.circle` and `arrow.clockwise` are both standard; `arrow.clockwise` already appears in this file's retry buttons. The message is `.secondary`, never `.red` — an empty list is a state of the account, not an error, and `.red` in this file is reserved for real failures.

**2. Empty domains** — replace the `case .loaded(let domains) where domains.isEmpty:` body in `domainField` with:

```swift
emptyState(
    "No domains on this account.",
    hint: "Check the server and username in Settings — they must match the MXRoute account that owns your domains."
) { Task { await model.loadDomains(force: true) } }
```

The hint points at server/username rather than the API key on purpose: a bad key fails with an authorization error and lands in `.failed`, so the realistic cause of a *successful* response with zero domains is credentials aimed at the wrong MXRoute account.

**3. Empty mailboxes** — replace the `case .loaded(let accounts) where accounts.isEmpty:` body in `destinationField` with:

```swift
emptyState(
    "No mailboxes on this domain.",
    hint: "A forwarder needs a mailbox to deliver to. Create one at panel.mxroute.com, then reload."
) { Task { await model.loadAccounts(for: model.selectedDomain, force: true) } }
```

`force: true` is mandatory on both reloads: `CreateForwarderModel` caches accounts per domain and short-circuits an already-loaded domain, so a plain reload after creating a mailbox in the panel would return the same empty list and the button would look broken.

**4. Leave every other branch alone** — `.idle` ("Choose a domain first."), `.loading` spinners, and `.failed` (red text + Retry) are all correct as they stand. Do not convert `.failed` to use `emptyState`: failures are red and this helper is deliberately secondary.

**5. Watch the height.** These branches are taller than the sentences they replace, and the popover has no fixed height, so it will grow when they appear — that is fine and expected. What is not fine is horizontal truncation: both hints must wrap, which is what `fixedSize(horizontal: false, vertical: true)` in the helper guarantees.

Finish with a clean build and the full regression suite.
