Create `README.md` at the repo root (none exists today) with exactly these sections, in this order. Write it for someone who has never seen the project — plain prose, no marketing tone, no emoji, no badges.

**`# MXRouteManager`** — then one or two sentences: a macOS menu bar app for creating MXRoute email forwarders in seconds. Click the menu bar icon, pick a domain, type an alias, pick the destination mailbox, press Create.

**`## What it looks like`** — a short text walkthrough of the popover rather than a screenshot (there is no screenshot in the repo and inventing an image path that does not resolve is worse than prose): the 320pt translucent popover, the Domain menu, the Alias field with its live `alias@domain` preview and inline validation, the "Forward to" menu of mailboxes on that domain, the Create button, and the confirmation line. One short paragraph. Do **not** add a `![screenshot](...)` reference to a file that does not exist.

**`## Requirements`** — macOS 15 (Sequoia) or later; Xcode 16 or later to build; an MXRoute account with API access. No third-party dependencies — SwiftUI and Foundation only.

**`## Building`** — the exact commands, including the DEVELOPER_DIR note, which is a real property of this environment and belongs in the README:

````
git clone <repo> && cd MXRouteManager

# Debug build
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project MXRouteManager.xcodeproj -scheme MXRouteManager \
  -configuration Debug -derivedDataPath /tmp/mxrm-build build

# Release build
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project MXRouteManager.xcodeproj -scheme MXRouteManager \
  -configuration Release -derivedDataPath /tmp/mxrm-release build

# Tests

  xcodebuild -project MXRouteManager.xcodeproj -scheme MXRouteManager \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath /tmp/mxrm-build -only-testing:MXRouteManagerTests test
````

Add one line explaining the prefix: the `DEVELOPER_DIR` prefix pins the Xcode toolchain; without it `xcodebuild` may resolve to the Command Line Tools and fail. Then note that the app is `LSUIElement` — after `open`ing the built app, look for the envelope icon in the **menu bar**, not the Dock, and that opening it in Xcode and pressing Run works too.

**`## Setup`** — the three credentials, as a numbered list, because this is the section a new user actually needs:

1. Sign in at `https://panel.mxroute.com` and go to **API Keys** (`panel.mxroute.com/api-keys.php`). Create a key and copy it — it is shown once.
2. That page also shows the values for **Server** (your mail server hostname, e.g. `eagle.mxlogin.com`) and **Username** (your DirectAdmin username). They also appear in your MXRoute welcome email.
3. Launch the app, open **Settings** from the popover (or the menu bar item's Settings…), enter Server, Username, and paste the API Key, then press **Save to Keychain**.
4. Press **Test Connection** — it fetches your domain list and reports how many domains it found. The first call from a newly built binary triggers a macOS Keychain prompt; choose **Always Allow** so it does not ask again.

**`## Security`** — the API key is stored in the macOS Keychain as a generic password (`MXRouteManager-APIKey`) and is never written to `UserDefaults`, a preference file, a log, or the repository. Server hostname and username are not secret and live in `UserDefaults` via `@AppStorage`. Presence of the key is checked attributes-only so that merely launching the app does not read the secret. The app talks only to `https://api.mxroute.com`.

**`## What it does not do`** — be explicit, because this is a deliberate MVP scope, not missing work: it does not list or delete existing forwarders (use the MXRoute panel); it does not create or manage domains or mailboxes; destinations are limited to mailboxes on the selected domain, so no external forwarding addresses; there is no launch-at-login option.

**`## Project layout`** — a short tree with one-line descriptions:

```

MXRouteManager/Models/       AppSettings, CreateForwarderModel, AliasValidator, API models
MXRouteManager/Services/     KeychainService, MXRouteClient
MXRouteManager/Views/        MenuBarContentView (the popover), SettingsView
MXRouteManagerTests/         55 Swift Testing cases
scripts/generate-appicon.swift   regenerates the app icon PNGs
.planning/                   roadmap, requirements, and per-phase plans

Tests are Swift Testing (`@Test`), run with the command above. The project was built phase by phase with the Kata workflow; `.planning/ROADMAP.md` and `.planning/phases/` hold the plans and verification records if you want the history.
