  <action>
Create `MXRouteManager/Views/SettingsView.swift` with a `SettingsView: View` that renders the shape Phase 2 will fill:

- a `Form` with `.formStyle(.grouped)`,
- one `Section("MXRoute Credentials")` containing a secondary-foreground line stating that API key, server, and username fields arrive in Phase 2,
- `.frame(width: 420, height: 200)` so the Settings window opens at a sane size instead of collapsing to its intrinsic height,
- a `#Preview { SettingsView() }`.

Do NOT add a `SecureField`, `TextField`, `@AppStorage`, or any Keychain code. Phase 2 (CONF-01..CONF-03) owns credential storage, and a half-built field here would have to be torn out — the Keychain decision is deliberately not made yet.

In `MXRouteManager/App/MXRouteManagerApp.swift`, add a second scene after the `MenuBarExtra` block:

```swift
Settings {
    SettingsView()
}
```

`Settings` must be a top-level scene in the `App` body — that is what makes macOS create the standard Settings window and what `SettingsLink` targets. Do NOT build a custom `Window`/`WindowGroup` for settings; a WindowGroup in a menu-bar-only app opens an unwanted window at launch, and `SettingsLink` would have nothing to open.

Leave the `MenuBarExtra` scene and its `.menuBarExtraStyle(.window)` modifier exactly as they are.

<task type="auto">
  <name>Task 2: Wire the Settings entry point into the popover</name>
  <files>MXRouteManager/Views/MenuBarContentView.swift</files>
  <action>
Replace the `// Settings entry point added in plan 01-02` marker in the bottom row of `MenuBarContentView` with:

```swift
SettingsLink {
    Label("Settings…", systemImage: "gearshape")
}
.simultaneousGesture(TapGesture().onEnded {
    NSApplication.shared.activate()
})
```

Place it before the existing `Spacer()` so Settings sits left and Quit stays right.

Two constraints, both load-bearing:

- Use `SettingsLink` (macOS 14+). Do NOT use `NSApp.sendAction(Selector(("showSettingsWindow:")), to: nil, from: nil)` — that string selector is undocumented, has already been renamed once across macOS releases, and fails silently when it breaks.
- Keep the `NSApplication.shared.activate()` gesture. This app is `LSUIElement`, so it is an accessory app that is never the active app; without an explicit activation the Settings window can open behind whatever the user was looking at and read as "nothing happened". Use `activate()`, not the macOS 14-deprecated `activate(ignoringOtherApps:)`.

`AppKit` is already imported in this file from plan 01-01 (the Quit button). Keep the Quit button unchanged.
  </action>
  <verify>
grep -n "SettingsLink\|NSApplication.shared.activate()\|terminate" MXRouteManager/Views/MenuBarContentView.swift
grep -rn "showSettingsWindow" MXRouteManager/ ; echo "expect no matches above"
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project MXRouteManager.xcodeproj -scheme MXRouteManager -configuration Debug -derivedDataPath /tmp/mxrm-build build 2>&1 | tail -5
  </verify>
  <done>`MenuBarContentView` contains a `SettingsLink` with an `NSApplication.shared.activate()` gesture and still contains the Quit button; no `showSettingsWindow` selector anywhere; build succeeds.</done>
</task>
